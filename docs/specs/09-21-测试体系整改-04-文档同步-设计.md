## 2. 关键决策与理由

### 决策 1：把「Tauri 原生产物」L3 准入原则写回规范

**决定**：修改 `docs/specs/desktop.test.md` §1，把「桌面端只验壳层职责」的口径**扩展**为明确、可机检的 L3 准入判据：

> **L3 准入原则**：只有当断言对象是 **Tauri 原生产物**时才允许建 L3 用例——独立 OS 窗口句柄、窗口几何夹紧、Tauri IPC 往返。业务面板、侧栏、tab、对话框等 dsh 内部 DOM 一律在 L2 用真实浏览器断言，不使用 L3。

**理由**：原 §1 的表述（「配置、语言、档案、插件生命周期等业务行为不属于壳层职责，不建 L3 用例」）与插件文档写下的 15 条 `-L3-*` 冲突，且**判据不够可操作**——「插件生命周期」是否包括「桌宠窗口创建」并不明确。子设计 02 已用该原则裁决：4 条 pet 窗口用例保留（真有独立 OS 窗口），11 条降级（都是 dsh 内部 DOM）。把原则写回规范，才能防止后续逐条侵蚀。

### 决策 2：同步修正两个 `00-overview.md` 的范围声明

**决定**：`docs/testing/desktop/00-overview.md` §1 与 `docs/testing/plugins/00-overview.md` 的分层/范围表述按决策 1 与新架构同步。

**理由**：`desktop/00-overview.md:3` 声称桌面端「已收敛为一条启动冒烟用例」，整改后该表述可能不再准确（若 4 条 pet L3 落地则需说明）；`plugins/00-overview.md:17` 写 L2 为「HTTP 断言先行，浏览器断言待接线」——整改后浏览器断言**已接线**，必须更新。

### 决策 3：修正已过期的缺口记录（G2）

**决定**：`docs/testing/plugins/00-overview.md:165` 的 G2 条目（「`playwright` 未出现在 `package.json` / `pnpm-lock.yaml` / `node_modules`，与 `plugin.test.md` §3.2 的 L2 浏览器方案冲突」）**已过期**——`node_modules/playwright`、`@vitest/browser`、`@vitest/browser-playwright` 均已存在，`pnpm-lock.yaml:6356` 有 `@vitest/browser-playwright: 4.1.11`。该条目须改写为当前真实状态（Playwright 已可用，且经子设计 01 决策 1 显式声明为依赖）。

### 决策 4：删除过期内容而非保留

**决定**：所有已被证否或不存在的方案描述**直接删除**，不留「已废弃」注记堆积。包括：任何指向 `@vitest/browser-*` 方案的表述、指向不存在文件的引用、`vitest.unit.config.ts` 已修的过期注释在文档侧的对应引用。

**理由**：本仓 `desktop/00-overview.md:4` 与 `00-overview.md:9` 的既有做法是「被移除的用例文档移入 `archive/docs/testing/`」；但**规范中已证否的方案描述**没有归档价值，保留只会误导后来者。用户需求④明确要求「删除过期内容」。

## 5. 错误语义

| 情形 | 期望行为 |
| --- | --- |
| 文档描述与实现不符 | **以实现为准修正文档**；若疑似实现缺陷，记录到文档缺口小节，不擅自改实现 |
| 发现文档条目多于/少于 `it()` | 判定为一处错误并修正到 1:1；不得为对齐数字而增删用例（用例增删属子设计 02/03） |
| 某方案（如 browser mode）已在规范中被证否 | **删除**描述，不留「待评估」占位 |
| 需求④与需求①②③的结论冲突 | 以①②③的实测结论为准修正文档；冲突本身记入 `history.md` |
| 归档目录内容 | **不读取、不引用、不搬回**（仓库最高优先级规则） |
