## 1. 目标

让 `docs/testing/plugins/` 描述的每一条用例都**真的会被执行**，并补上当前完全空白的**客户端渲染与真实浏览器行为**覆盖。核心量化事实：文档声明 **107** 条，实际 `it()` 仅 **55** 条，缺口 **52** 条；且现有 55 条**没有一条**能验证客户端行为——`test/e2e/plugins/` 对 `document.`/`window.`/`playwright`/`chromium` 的引用数为 **0**，根因是 `vitest.plugin.config.ts:22` 的 `environment: 'node'`。

## 2. 关键决策与理由

### 决策 1：L3 收敛为「Tauri 原生产物」原则

**决定**：**只有当断言对象是 Tauri 原生产物时才允许建 L3 用例**——即：独立 OS 窗口句柄、窗口几何夹紧、Tauri IPC 往返。其余一律不得使用 L3。

**理由**：本仓 `docs/specs/desktop.test.md` §1 明确「只验壳层职责」，并把配置、语言、档案、**插件生命周期**排除在 L3 之外；而插件文档写下了 15 条 `-L3-*`，形成直接冲突。需要一个**可机检、可复述**的判据来裁决，否则原则会被逐条侵蚀。该判据的判别力来自实测：15 条中只有 **4 条 pet 用例**断言真正 Tauri 原生的东西（独立桌宠窗口的存在/不存在/创建销毁/几何夹紧），其余 **11 条**断言的都是嵌在 dsh iframe 内部的 DOM（面板 / 侧栏 / tab / 对话框），在浏览器里同样可验。

**落地**：

- **KEEP 为 L3（4 条）**：`TC-PET-L3-02-001`（启用后出现独立桌宠窗口）、`TC-PET-L3-02-002`（`[反向]` 未启用时无桌宠窗口）、`TC-PET-L3-02-003`（侧栏入口切换后窗口创建与销毁）、`TC-PET-L3-02-004`（桌宠尺寸边界夹紧 50–200）。
  > **⚠️ 运行归属（关键，否则这 4 条永不执行）**：这 4 条**不使用** `plugin` project，而是落到 **`desktop` 车道**，新建 `test/e2e/desktop/02-pet-window.e2e.ts`，由 `desktop` project 匹配（`vitest.desktop.config.ts:15` 的 `include: ['test/e2e/desktop/*.e2e.ts']` **已能匹配，无需改 config**）。
  > 原因：`desktop` project 的 include 只收 `test/e2e/desktop/*.e2e.ts`，永远收不到 `test/e2e/plugins/` 下的用例；而 `plugin` project 的 CI 作业是 **ubuntu-latest**（`ci.yml:80`），`build:debug`/Tauri 是 **Windows-only**（`desktop-e2e` = windows-latest，`ci.yml:119`）。若把它们留在 `plugin` 文件里，就会出现「写了却永不执行」的假绿——正是本次整改要消除的模式。
  > **前置**：`pnpm build:debug` + Windows；**运行**：`pnpm test:e2e:desktop -- --run`。
  > **文档代价（由子设计 04 收口）**：`plugin.test.md` §4 规定「一个编号只允许一个测试文件」，本批次因此需要为该规则写一条**明确例外**：批次 `02` 的 L2/浏览器用例在 `test/e2e/plugins/02-*.e2e.ts`，其 L3 段在 `test/e2e/desktop/02-pet-window.e2e.ts`；两文件的 `it()` 合计须等于文档 `[Case ID]` 数。
- **DOWNGRADE 为 L2/浏览器（11 条）**：`TC-RC-L3-03-001`、`TC-RC-L3-03-002`、`TC-SESS-L3-04-001`、`TC-SESS-L3-04-002`、`TC-WT-L3-05-001`、`TC-UI-L3-06-001`、`TC-UI-L3-06-002`、`TC-EXT-L3-07-001`、`TC-SCH-L3-08-001`、`TC-REW-L3-09-001`、`TC-MC-L3-10-001`。降级即改写为在真实浏览器中驱动真实 dsh UI 的断言，**不是删除**。

> **该原则本身需写回规范**：`docs/specs/desktop.test.md` §1 与两个 `00-overview.md` 的范围声明须同步修正——这是子设计 04 的工作；本设计只负责按其落地用例。

### 决策 2：真实 DOM 覆盖走 Playwright 库 API，不新增 project

**决定**：全部客户端/浏览器类用例在现有 `plugin` project（node 上下文）内，用 `import { chromium } from 'playwright'` 驱动真实 Chromium，访问 `globalSetup` 已启动的真实 dsh web 宿主，复用 `inject('dshBaseUrl')` / `inject('dshCookie')`。

**理由**：与子设计 01 决策 3 同源——符合 `plugin.test.md` §3.2 既有明文（Playwright 库 API，不引入 Test Runner）与 `00-overview.md:102` 的宿主最小化原则。

**关键工艺约束（用例必须遵守）**：

1. **鉴权必须带 Cookie**：dsh 只接受「根路径 `GET /?token=<...>` 换 Cookie」这一条通道（`plugin.test.md` §5 鉴权说明）。Playwright 上下文需先 `addCookies` 注入 `globalSetup` 已换取的会话凭据，否则 `/api` 与插件路由一律 401。
2. **插件 client 只在内嵌 frame 内生效**：`dsh-tauri` 与 `dsh-tauri-pet` 的 client 入口都有 `window.parent === window` 早退（`packages/dsh-tauri/src/client/apply.ts:29`、`packages/dsh-tauri-pet/src/client/index.ts:24`）；`00-overview.md` §2 冲突 5 与 G6 亦记录该事实。因此**顶层页面断言槽位必然失败**，必须构造 iframe 环境或使用 dsh 自身的嵌入形态。
3. **选择器按「元素归属」分流**（实测确认，非二选一）：
   - **插件自身注入的元素**用 **`data-dsh-*`**——这是插件 client 实际发出的属性，例如 `worktree` 的 `data-dsh-worktree-surface`/`data-dsh-worktree-dialog`（`packages/dsh-tauri-worktree/src/client/constants/index.ts:40,47`）、`pet` 的 `data-dsh-tauri-pet-icon`（`packages/dsh-tauri-pet/src/client/constants/index.ts:38`）、`session` 的 `data-dsh-tauri-session-archive-item`（`packages/dsh-tauri-session/src/client/constants/index.ts:31`）。**注意其中一部分是行为钩子而非纯测试锚点**（`ui` 的 `obstructions.ts:88` 以 `attributeFilter` 观测 `data-dsh-better-sidebar`/`data-slot`），因此**不得**为测试方便随意改动这些属性名。
   - **壳层 `src/` 提供的元素**用 **`data-testid="dsh-<业务域>-<元素名>"`**（`desktop.test.md` §5），如 `dsh-shell-iframe`、`dsh-config-dialog`。
   - **dsh 内部结构**属上游产物，可用稳定结构性锚点并在缺口小节登记（§5 例外条款）。
   > ⚠️ **须由子设计 04 收口的口径**：`plugin.test.md:133`（「必须使用 `data-dsh-*`」）与 `desktop.test.md` §5（`data-testid`）各自只覆盖自己的域，**两者并不冲突**，但都未写明对方的存在，读者会误以为互相排斥。子设计 04 须为两者各补一句**适用范围**（插件包 `packages/*` → `data-dsh-*`；壳层 `src/` → `data-testid`），并新增本层的定位口径。浏览器用例按上述分流编写。
4. **禁止 CSS 类名 / 文案 / DOM 层级定位**（`plugin.test.md` §6 禁止项）。

### 决策 3：新增 `dsh-tauri-connection` 覆盖（第 11 个批次）

**决定**：为 `packages/dsh-tauri-connection` **新建**用例文档与测试文件（编号 `11`），补上最低 3 条 L2 覆盖。

**理由**：它是全仓**唯一的网络安全边界型插件**，却在 `docs/testing/` 中**完全没有文档**，E2E 覆盖为 0，仅有进程内单测（`packages/dsh-tauri-connection/src/host/service/gate.ts` 的 `gate.test.ts:37-90`）。其契约具有高安全含义：`gate.ts:12,24` 在 `DSH_TAURI_EMBEDDED === '1'` 时 `:36-39` 把 **401 降级为放行**、`:40` `authorizeIndex = () => true`（**索引无条件放行**）、`:42-45` detach 还原。零端到端证据的安全边界不可接受。

## 4. 目标用例量（量化指标）

层别定义：`-L2-*` = 宿主 HTTP/文件系统契约；`-C-*`/浏览器 = 真实 Chromium 驱动真实 dsh UI；`-L3-*` = Tauri 原生产物。

| 01 | host + core contract | 12 | 12 | 0 | 0 | 12 | — |
| 02 | `dsh-tauri-pet` | 5 | 5 | 4 | **4** | 13 | 既有 `-C-*` 4（pet 的 4 条 L3 全保留，无降级） |
| 03 | `dsh-tauri-rightclick` | 4 | 5 | 6 | 0 | 11 | 既有 4 + 降级 L3 2 |

**推导说明**：

- 目标 L2 合计 83 来自逐包契约与未触及路由盘点。
- 浏览器 43 = 既有 `-C-*` **29** + 降级 L3 **11** + 新增高价值行为 **3**（逐套件落位见上表「浏览器增量来源」列，`29+11+3=43`）。
- **新增的 3 条严格对应 §2 决策 4 中风险最高的三类**，即：`04` 的归档面板无 error boundary（宿主崩溃）、`05` 的 fiber 图标走查（静默失效）、`07` 的重启失败报成功（**把失败报成成功**）。
- `01` 保持 12 条不变（其 L2 与共享契约已饱和）。
- **§2 决策 4 的其余 9 类行为不在本轮预算内**，但**必须登记为文档缺口**（写入 `00-overview.md` 与各文件末节），不得静默丢弃——这满足用户需求②「列出缺失的重要测试」，同时不让「+3」承担它无法承担的 8 类。§2 决策 4 的「至少覆盖前 8 类」据此修正为「**登记全部，预算内优先覆盖风险最高的 3 类**」。

**为何目标合计 130 > 文档现值 107（不是算术错误）**：按层拆解如下，差额来源明确：

| 层 | 文档现值 | 目标下限 | 差 | 差额来源 |
| --- | --- | --- | --- | --- |
| `-L2-*`（宿主 HTTP/文件系统） | 63 | **83** | **+20** | 未触及路由补齐（model-config 0→5、extension 8→19、scheduler 6→10、session 7→9、ui 分支）、新建 connection 批次 +3、8 条 `-L2-*` 缺口 |
| 浏览器 / `-C-*` | 29 | **43** | **+14** | 11 条降级 L3（改写为浏览器断言）+ 3 条新增高价值行为（fiber 走查、extension 静默成功、session 无 error boundary） |
| `-L3-*`（Tauri 原生产物） | 15 | **4** | **−11** | 按「Tauri 原生产物」原则收敛，仅留 4 条 pet 窗口用例 |
| **合计** | **107** | **130** | **+23** | — |

> 简言之：**文档现值 107 本身就是不完整的基线**——它既没为已接线的 55 条设计任何客户端部分，又整包漏掉 `dsh-tauri-connection`。130 是补齐后的新基线下限。差额由用户需求②「很多真实的场景都没测」驱动，**不是为凑数字的用例膨胀**。

**注**：本表是**验收下限**，不是上限。放宽方式只能在实现时以「该契约不可达」为理由并记录到 `history.md`，不得为提高数字而写低价值用例。

## 6. 错误语义

| 情形 | 期望行为 |
| --- | --- |
| `playwright` 缺失或 Chromium 二进制缺失 | **整批失败**（子设计 01 §6）；不得跳过浏览器用例 |
| `pnpm build:plugins` 未执行 | `dsh-host.ts` 直接失败并提示需跑的命令（既有行为，保持）；不得静默跳过 |
| dsh 宿主未就绪 | 整批失败（既有行为） |
| 浏览器用例无法取得会话 Cookie | 用例失败并指明鉴权步骤，不得降级为「只断言 HTTP 状态」 |
| 目标插件未被挂载 | 用例失败（`assertMountRegistered` 既有行为） |
| 断言发现文档与实现不一致 | **不改断言求绿**：记录为疑似缺陷或文档过期，按实测修正，并把差异登记到该文件末节的缺口小节 |
| 需要真实模型/网络/系统副作用的用例（如 rightclick 正向 200 会真的拉起浏览器、scheduler `run_now`） | 保持**手工执行**或标注待补，**不写自动化假绿**；须在文档 `[自动化]` 字段如实标注 |
