# 测试体系整改 — 主设计

> **状态**：待批准
> **适用范围**：`deepseek-harness-desktop` 全仓测试体系（桌面端 `src/` + `src-tauri/`、内置插件 `packages/*`、`test/**`、`docs/testing/**`、`docs/specs/*.test.md`）
> **事实基线**：[`.temp/brainstorm-test-overhaul-facts.md`](../../.temp/brainstorm-test-overhaul-facts.md)（三份调查的完整证据与行号，本主设计的量化结论均出自此文件）
> **子设计**：见 §3

---

## 1. 总目标

在不引入第二套测试运行器、不牺牲「真实宿主」覆盖的前提下，完成四件事：

1. **架构收敛**：放弃「用 Vitest browser mode 取代自定义宿主编排」的方案（已证不可行），确立**Node 上下文 + Playwright 库 API** 作为真实 DOM 覆盖的唯一新增通道，并保留现有已在官方推荐路径上的宿主编排。
2. **补齐插件 E2E 的真实场景**：把 `docs/testing/plugins/` 中已设计但未接线的用例补齐，重点是当前**一条都没有**的客户端渲染与真实浏览器行为。
3. **全面审查 / 优化 / 精简单测**：消除「假信心测试」，按「改写优先」策略收敛重复与恒真用例，补齐高价值零覆盖契约，并建立可机检的质量门禁。
4. **文档与规范全面同步**：修正所有过期事实、口径冲突与元数据错误，使 `docs/testing/**` 与 `docs/specs/*.test.md` 如实描述整改后的测试体系。

**成功判据（整体）**：四份子设计的验收标准全部达成；`pnpm test:unit`、`pnpm test:e2e:plugin`、`pnpm test:e2e:desktop` 三条命令在本机与 CI 均如实通过；`docs/testing/**` 中不存在与本仓实现相矛盾的陈述。

| CI | `.github/workflows/ci.yml` 的 unit / plugins-e2e / desktop-e2e 三个作业 |

### 2.2 非目标

1. **不引入 `@vitest/browser` 系列**（`@vitest/browser-webdriverio` / `@vitest/browser-playwright`）。判定依据见子设计 01 §2，属已证否方案，不再重新评估。
2. **不引入 Playwright Test Runner**，也不引入 `@wdio/cli` / `wdio.conf.ts`。全仓保持**唯一运行器 Vitest**，Playwright 与 WebdriverIO 只作为驱动库。
3. **不删除 `test/e2e/support/dsh-host.ts` 与 `test/e2e/support/desktop-host.ts`**（原需求曾要求删除，经可行性验证后改为保留）。
4. **不改动被测业务行为**。整改只允许改测试、测试基础设施与文档；若发现测试与实现矛盾，按「实现或测试有一条错」定位并记录，不为了让测试变绿而放松断言。
5. **不覆盖 `source/`（vendored dsh 核心）、`archive/`、`test/archive/`**。`archive/` 一律不读取。
6. **不追求全局覆盖率百分比门槛**：`@vitest/coverage-v8` **安装并生成报告**，但覆盖率**不设阈值、不卡关、不进 CI 门禁**（理由见子设计 03 决策 1、2）。
7. **不修改 `packages/*` 的对外契约与产物结构**（本轮整改不触碰构建产物定义）。

```
         └───────────────┬──────────────┘
                         │
   03 单测质量 ──────────┤（与 01/02 无依赖，可完全并行）
                         │
                         ▼
         ┌──────────────────────────────┐
         │ 04 文档同步（如实反映最终状态） │
         └──────────────────────────────┘
           软依赖：01、02、03 的用例与状态落定后才可收尾
```

| 分组 | 子设计 | 可并行性 |
| --- | --- | --- |
| 第 1 波 | **01 架构** 与 **03 单测质量** | 两者无交集（01 只碰 e2e 配置与编排，03 只碰单测与 unit 配置），可并行 |

| 第 3 波 | **04 文档同步** | 必须最后执行；依赖 01–03 的最终用例编号、条数与状态 |

## 5. 整体验收

1. **子设计验收**：01–04 各自的「验收标准」全部达成，且每条验收标准都有可复现的命令或可核对的产物。
2. **命令真实性**：以下命令在整改后的工作区**实际运行**并给出通过结果（不得只做静态检查）。**每条命令都有明确归属的子设计**，不得无人执行：

   ```bash
   pnpm test:unit -- --run                                     # 归属：03
   pnpm build:plugins && pnpm test:e2e:plugin -- --run        # 归属：02
   pnpm build:debug && pnpm test:e2e:desktop -- --run         # 归属：02（4 条 pet L3 用例；Windows only）
   ```
   > `test:e2e:desktop` **必须**有人跑：子设计 02 新建的 `test/e2e/desktop/02-pet-window.e2e.ts` 在 `desktop` project 下，若无人执行就等于「写了却永不运行」。

3. **无假信心残留**：子设计 03 定义的 blocker 类问题**归零**，且该结论由实际运行 + 必要的变异验证（故意破坏实现确认测试会红）支撑。
4. **文档一致性**：`docs/testing/**` 与实际 `it()` 数量、编号、层级分布**逐项一致**；不存在指向不存在文件的引用、不存在与实现矛盾的陈述。
5. **规范一致性**：`docs/specs/desktop.test.md` 与 `plugin.test.md` 描述的驱动方案、层级边界、L3 准入原则与最终实现一致。
6. **零环境越界**：全程无任何测试读写用户真实的 `~/.dsh`、`~/.dsh.dev`、`.store.dat`、`.store.dev.dat`。

## 6. 关键约束（适用全部子设计）

1. **不改测试求绿**：测试与实现不符时，定位哪一条错并留证；只有明确要求「修测试」时才动手，且不得放松断言。
2. **跑过的才算通过**：静态阅读不能作为「测试没问题」的依据。评审与验收命令一律显式带 `run`（本仓 `test`/`test:unit`/`test:e2e:*` 脚本**不带** `run`，交互式终端会进 watch 挂住）。
3. **单文件过滤用位置参数**：`vitest run --project unit <file>`；带 `--` 的写法**不过滤**，会跑完整个 project。
4. **配置层事实**：四个 vitest 配置均**无** `globals: true`，也**无** `restoreMocks`/`clearMocks`。因此「显式 import」「文件自管 mock 还原」是**正确**写法，不要反向要求全局 API。
5. **环境隔离**：L2 用 `DSH_E2E_HOME`，L3 用 home 重定向；禁止触碰用户真实数据目录。
6. **文档同步义务**：行为改动必须同时更新用例文档与测试代码（一条文档条目 ↔ 一个 `it()`），并登记 `progressive.md` §4 台账与 `history.md`。
7. **不构建插件**：处理插件时不要执行构建（用户可能正在运行 dev）；确需构建产物时先确认。
8. **0 注释原则**：只在关键节点添加注释；清理冗余注释。
